# Testing

> Testing strategy and what must pass before a change is accepted.

## Strategy

Three layers. Unit tests (Vitest, jsdom) cover ingest, pipeline and tokens. Browser drives run the real served bundle in Chromium. An adversarial probe attacks the print endpoint. The project's history shows the unit suite stayed green while several real bugs existed. Those were found only by driving Chromium or inspecting screenshots (`tasks/todo.md`), so do not treat green unit tests as sufficient for UI, export or server changes.

`definition_of_done.md` lists criteria with the command that proves each one.

## Unit Tests

- Runner: Vitest 3, `environment: 'jsdom'`, `tests/setup.ts` as setup, `@` aliased to `src`. Includes `tests/**/*.test.ts(x)`.
- Files: `tests/unit/docset.test.ts`, `fixtures.test.ts`, `ordering.test.ts`, `pipeline.test.ts`, `tokens.test.ts`, `walker.test.ts`.
- Run: `npm test` (watch mode) or `npm test -- --run` (once).
- Count: the README and `tasks/todo.md` report 121 tests at the last recorded gate. This was not re-run.
- The definition of done refers to filters such as `npm test -- links` or `-- sanitize`. Those match test file names, and not all such files exist. For example, there is no `links.test.ts` or `sanitize.test.ts` among the listed files, so those may live inside `pipeline.test.ts` or `docset.test.ts`: uncertain — verify with developer.

## Integration Tests

None separate from the unit and browser suites. `tests/fixtures/handbook/` is a fixture folder (nested directories, an image, a messy markdown file, a non-markdown file) used by unit tests and the browser drives.

<!-- sources: tests/e2e/make-fixtures.mjs, tests/e2e/run.sh -->

## End-to-End Tests

`npm run test:e2e` (`tests/e2e/run.sh`) regenerates fixtures (`make-fixtures.mjs`) and runs each drive in a sibling container that shares the app container's network namespace, using the built image.

| Drive | Covers |
|---|---|
| `drive.mjs` (ingest) | walker, reading order, grouping, titles, skips |
| `drive-reader.mjs` (reader) | navigation, keyboard, responsiveness, axe accessibility, reduced motion |
| `drive-export.mjs` (export) | both exports, re-opened with the network blocked |
| `shots.mjs` | screenshots into `tests/e2e/shots` (run as part of `all`) |

Run one with `bash tests/e2e/run.sh reader` (names: `ingest`, `reader`, `export`, `adversarial`). Requires the app container running: default name `markdown_visualiser-app-1`, image `markdown-visualiser:local`.

<!-- sources: tests/e2e/run.sh, README.md -->

## Security Tests

`npm run test:security` runs `tests/e2e/adversarial.mjs` against the running container. It covers `file://` reads, internal and metadata addresses, CSS-only SSRF, script execution, oversized bodies (413), concurrency saturation (429), malformed bodies (400) and error-text disclosure. The last recorded result is 11 of 11 checks (`tasks/todo.md`). This was not re-run.

Sanitiser behaviour is covered by hostile-payload unit tests: `tasks/todo.md` says 13 payload tests exist. The unit tests were not read for this document.

<!-- sources: tests/e2e/run.sh, tasks/todo.md, README.md -->

## Manual and Smoke Tests

```bash
docker compose up --build -d
curl -sf localhost:8080/healthz          # status ok, browser idle before first PDF
```

Then open `http://localhost:8080`, drop `tests/fixtures/handbook`, click through the index, export HTML and PDF, and open the HTML with the network disabled. Definition-of-done items 4.1 and 4.2 are manual checks.

<!-- sources: definition_of_done.md, server/index.ts -->

## Test Environments and Data

Unit tests need only Node (`engines` says 20 or later; the image builds with 24). E2E and security tests need Docker. Fixtures live in `tests/fixtures/handbook/` and are also regenerated by `tests/e2e/make-fixtures.mjs`. No external services, credentials or databases are involved.

<!-- sources: package.json, tests/e2e/run.sh, tests/setup.ts -->

## Running Tests

```bash
npm run typecheck
npm run lint            # --max-warnings 0
npm test -- --run
docker compose up --build -d
npm run test:e2e
npm run test:security
```

<!-- sources: package.json, tests/e2e/run.sh -->

## Required Before Changes

- Every change: `npm run typecheck`, `npm run lint`, `npm test -- --run` must pass with no warnings.
- Changes to `src/pipeline/`, `src/export/`, `src/reader/` or `src/ingest/`: also `npm run test:e2e`.
- Changes to `server/`, `Dockerfile`, `docker-compose.yml` or `sanitize.ts`: also `npm run test:security`.
- No CI job runs these checks. The only workflow is the docforge documentation check, so they must be run locally: uncertain — verify with developer.
